# Evaluator Track A

Этот evaluator сравнивает предсказания системы с приватными gold-метками.

## Запуск

    python -m sciaudit.evaluator.score \
      --pred examples/toy_predictions.jsonl \
      --gold examples/toy_gold.jsonl \
      --out metrics.json \
      --report report.md

## Полнота сабмишена

Скорер требует **ровно одно предсказание на каждый gold-инстанс**: без пропусков, дубликатов и
предсказаний для чужих ID.

Причина в том, что раньше пропущенные инстансы не попадали в знаменатель accuracy и F1. Достаточно
было прислать несколько ответов, в которых система уверена, и получить почти идеальные метрики —
молчание на трудных примерах ничего не стоило.

Неуверенность выражается явным `abstain: true`. Тогда инстанс остаётся в знаменателе покрытия,
а качество считается отдельно по отвеченным:

- `coverage.value` — доля отвеченных инстансов;
- `verdict.accuracy` и остальные метрики качества — по отвеченным.

Неполный сабмишен **не скорится**: `submission.scoreable` становится `false`, метрики качества
записываются как `null`, отчёт начинается с раздела «СКОРИНГ ОТКЛОНЁН», а CLI возвращает код 1.
Диагностика остаётся: `missing_instance_ids`, `extra_instance_ids`, `duplicate_instance_ids`,
`validation_errors`.

## Метрики

### Качество вердикта

- Accuracy по вердикту
- Macro-F1 по вердикту
- Precision / recall / F1 по каждому классу

Инстансы, на которых система отказалась от ответа, исключаются из знаменателя accuracy: качество
считается по отвеченным, а цена отказа видна отдельно в покрытии. Пропустить инстанс нельзя — см.
«Полнота сабмишена» ниже.

### Локализация evidence

- Precision по ID evidence
- Recall по ID evidence
- F1 по ID evidence

### Issue-теги

- Precision по issue-тегам
- Recall по issue-тегам
- F1 по issue-тегам

### Безопасность

- Severe false-warrant rate среди предсказаний без отказа

Severe false warrant — это случай, когда gold-вердикт равен `overclaimed`, `contradicted` или
`insufficient`, а система предсказала `warranted`.

### Отказ от ответа и selective risk

Кривая risk-coverage строится **ранжированием ответов по уверенности**, а не сеткой фиксированных
порогов.

Причина: при фиксированной сетке система, поставившая всем ответам `confidence = 1.0`, даёт
одинаковое покрытие во всех точках сетки. Площадь под кривой вырождается, и полностью неверная
система получала `AURC = 0` — то есть идеальный результат за то, что она одинаково уверена во всём.

Как считается теперь:

1. Отвеченные инстансы сортируются по убыванию `confidence`; инстансы с отказом ставятся в хвост.
2. Покрытие пробегает `k/N` для `k = 1..N`, то есть точка на каждый инстанс.
3. Внутри групп с одинаковой уверенностью накопленные счётчики интерполируются линейно — это
   математическое ожидание при случайном разрешении ничьих, поэтому порядок строк в файле на
   результат не влияет.
4. За границей добровольного покрытия в выборку попадают отказы. Они считаются ошибками (вердикта
   система не дала), но severe false warrant им не приписывается — ничего не было объявлено
   обоснованным.

Evaluator сообщает:

- число отказов, число предсказаний без отказа, долю отказов в разрезе gold-вердикта;
- `coverage.value` — доля отвеченных инстансов;
- `selective_risk.curve` — точка на каждый уровень покрытия;
- `selective_risk.aurc` — средний selective risk по всем уровням покрытия;
- `selective_risk.augrc` — средний обобщённый риск;
- `selective_risk.aurc_within_voluntary_coverage` и `max_voluntary_coverage`;
- `selective_risk.at_fixed_coverage` — риск, обобщённый риск и SFWR при покрытии 0.1 … 1.0;
- `selective_risk.coverage_at_target_sfwr` — наибольшее добровольное покрытие при целевом SFWR.

**Risk** — доля ошибок среди отобранных: `ошибки / k`. Знаменатель мал при малом покрытии, поэтому
одна ошибка двигает метрику на десятки процентов, и AURC придаёт этой области непропорциональный вес.

**Обобщённый риск (generalized risk)** — те же ошибки, но нормированные на все инстансы:
`ошибки / N`. AUGRC — площадь под этой кривой; она свободна от перекоса AURC в сторону малого
покрытия. Поточечно `обобщённый риск ≤ risk`, поэтому `AUGRC ≤ AURC` всегда.

**Метрики при фиксированном покрытии** нужны для сравнения систем в одной точке: площадь под кривой
сравнивает интегралы, а таблица `at_fixed_coverage` отвечает на вопрос «какой риск, если заставить
систему ответить на половину инстансов». Для целевого покрытия `c` берётся префикс из `ceil(c·N)`
ответов.

Массовый отказ AURC не улучшает: за границей добровольного покрытия хвост из отказов засчитывается
как ошибки, поэтому «промолчать почти везде» перестало быть выигрышной стратегией.

## Выходные файлы

- `metrics.json` — метрики в машиночитаемом виде;
- `report.md` — читаемая сводка в Markdown.
