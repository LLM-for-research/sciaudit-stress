# Бейзлайн B2: аудит по полному evidence pack

B2 — научный контроль к B1, а не попытка выиграть у него. Модель вызывается
точно так же, но в промпт подаётся весь evidence pack инстанса, без ретрива.
Вопрос, на который отвечает пара B1/B2: помогает BM25 или мешает.

## Запуск

```bash
python -m sciaudit.baselines.b2_fullpack_llm \
  --input data_public/public_warmup/inputs.jsonl \
  --output predictions.jsonl \
  --model-command "your-open-model-command" \
  --model-name "your-open-model-id"
```

CLI совпадает с B1 за вычетом `--top-k`: у B2 нет бюджета ретрива, и аргумент
намеренно не принимается, чтобы прогон нельзя было настроить «наполовину».
Коды возврата те же: `0` — успех, `1` — все инстансы ушли в безопасный отказ,
`2` — ошибка использования.

## Почему различие ровно одно

Промпт, вызов модели, разбор ответа, нормализация до схемы, безопасный отказ и
контракт CLI лежат в `sciaudit/baselines/model_audit.py` и используются обоими
бейзлайнами. В B1 остаётся BM25, в B2 — функция, возвращающая пак целиком.

Это не стилистика, а условие корректности контроля: если бы у B1 и B2
отличались промпты или обработка отказов, разница в метриках перестала бы
относиться к ретриву. Совпадение реализаций сторожит тест
`test_both_baselines_use_the_same_shared_implementation`.
