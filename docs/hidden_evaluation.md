# Скрытый контур: нарезка и репетиция оценки

Скрытый сплит — это не «данные, которые мы никому не показали», а данные,
которые **нельзя вывести** из показанного. Отсюда всё устройство этого контура.

Два модуля:

* [`make_hidden_split`](../sciaudit/construction/make_hidden_split.py) — режет
  приватные аннотации на публичный, скрытый валидационный и финальный скрытый
  срезы (§10.4, §10.5);
* [`hidden_dry_run`](../sciaudit/evaluator/hidden_dry_run.py) — прогоняет
  оценку по скрытому срезу целиком, до того как он появится по-настоящему
  (§8.1, шаг 7).

## Почему граница проходит по группам, а не по инстансам

| Группа | Что в неё входит | Что ломается, если разрезать |
|---|---|---|
| **статья** | все инстансы одной публикации | инстансы делят таблицы, числа и терминологию; скрытый срез начинает мерить память о конкретной таблице, а не обобщение |
| **seed** | исходный инстанс и все его стресс-варианты | стресс-вариант отличается от seed одним контролируемым изменением — вариант в скрытом срезе при публичном seed это готовая подсказка |

Соблюдаются обе: инстансы собираются в seed-группы, seed-группы — в группы
статей, и в сплит уходит группа целиком. Разложение жадное и детерминированное:
большие группы первыми, каждая уходит в сплит, который дальше всех от своей
доли. Случайности здесь нет намеренно — при десятках инстансов она только делает
результат невоспроизводимым.

```bash
uv run python -m sciaudit.construction.make_hidden_split \
  --internal data_paper_derived/*.internal_annotation.jsonl \
  --by paper --student-out /tmp/student --staff-out /tmp/staff
```

`--by paper` — строгий режим, которого требует §10.4. `--by seed` слабее: одна
статья окажется по обе стороны, и модуль об этом громко предупреждает, потому
что молчаливо ослабленная гарантия хуже, чем названная.

## Две половины

Нарезка всегда пишет **две** директории, и это её главное свойство:

| | Что кладётся | Кому |
|---|---|---|
| `--student-out` | `inputs.jsonl`; для публичного среза ещё и `gold.jsonl` | участникам |
| `--staff-out` | `gold.jsonl` для каждого среза | штабу |

Скрытый gold на студенческую сторону не попадает никогда — это §10.5 дословно:
участники получают только входной JSONL.

Проекция в публичный вид переиспользуется из `derive_public.py`. Вычёркивание
приватных полей обязано иметь ровно одну реализацию: две разойдутся, и разойдутся
молча.

## Репетиция

```bash
uv run python -m sciaudit.evaluator.hidden_dry_run \
  --internal data_paper_derived/*.internal_annotation.jsonl --by seed
```

Пять шагов, у каждого право уронить репетицию:

1. нарезка по группам — статья и её стресс-варианты не расходятся;
2. **проверка студенческой половины** — ни `gold.jsonl`, ни приватных полей внутри строк;
3. прогон B0 по студенческому входу — тем же CLI, каким сдают участники;
4. валидация предсказаний по схеме;
5. скоринг на штабной стороне и отчёт.

Второй шаг — единственная причина, по которой это не «ещё один прогон
evaluator'а». Проверяется **отсутствие** того, чего быть не должно, а такую
ошибку нельзя заметить по метрикам: если gold уедет к участникам, метрики станут
только лучше.

Бейзлайн по умолчанию B0 — он не ходит в модель, поэтому репетиция ничего не
стоит и гоняется в CI на каждом коммите. Рабочая директория временная: скрытые
входы не должны оставаться лежать в репозитории после репетиции.

## Что получается на сегодняшних данных

```
репетиция скрытой оценки на срезе hidden_val (7 инстанс(ов), статьи P001, P002)
  нарезка по: seed; размеры сплитов: hidden_test=5, hidden_val=7, public=12
  студенческая половина: только inputs.jsonl, приватных полей нет
  B0 отскорен штабом: accuracy 0.000, coverage 1.000
  ВНИМАНИЕ: статьи по обе стороны границы — P001, P002
ПРОЙДЕНА
```

**Механика работает, данных не хватает.** В строгом режиме `--by paper` две
статьи на три сплита не делятся, и модуль честно падает:

```
сплит hidden_test заказан, но пуст: неделимых групп меньше, чем сплитов
```

Это не дефект нарезки, а точное сообщение о состоянии датасета. Чтобы скрытый
контур заработал по-настоящему, нужны статьи: §8.3 требует 30–40 в пуле, 40–60
инстансов в скрытой валидации и 30–40 в финальном резерве. Сейчас в пуле две.

До тех пор репетиция гоняется в режиме `--by seed`: она проверяет весь путь от
приватной аннотации до метрик и ловит любую ошибку в механике — кроме той, от
которой защищает только объём.
