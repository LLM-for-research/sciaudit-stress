# Бейзлайн B1: BM25 + структурированный аудит моделью

B1 — первый нетривиальный бейзлайн после B0. Он отбирает из evidence pack
наиболее релевантные единицы по BM25 и просит модель вернуть строгий JSON с
вердиктом. Смысл бейзлайна научный, а не соревновательный: он показывает,
сколько даёт голый ретривал плюс одна модель без численного чекера, отдельного
абстейна и подбора промпта.

## Запуск

Команда модели обязательна: без неё B1 отказывается работать, а не тихо
превращается в B0.

```bash
python -m sciaudit.baselines.b1_bm25_llm \
  --input examples/sample_inputs.jsonl \
  --output predictions.jsonl \
  --top-k 3 \
  --model-command "your-open-model-command" \
  --model-name "your-open-model-id"
```

Промпт подаётся команде в stdin, ответ читается из stdout.

| Аргумент | По умолчанию | Что делает |
|---|---|---|
| `--input` | — | JSONL со входами Track A |
| `--output` | — | JSONL с предсказаниями, по строке на вход |
| `--top-k` | 3 | сколько единиц evidence отбирает BM25 |
| `--model-command` | — | shell-команда инференса |
| `--model-name` | `b1-open-model` | идентификатор модели для `system_info.model` |
| `--retries` | 1 | повторов после неразобранного ответа |
| `--timeout-seconds` | 60 | таймаут одного вызова |

Коды возврата: `0` — успех, `1` — все инстансы ушли в безопасный отказ,
`2` — ошибка использования или чтения входа.

## Где что лежит

Промпт, вызов модели, разбор ответа, нормализация, безопасный отказ и контракт
CLI общие с B2 и живут в `sciaudit/baselines/model_audit.py`. В самом B1
остаётся только ретрив. Так сделано ради контроля B1/B2: различаться бейзлайны
обязаны ровно наличием BM25, иначе сравнение в
[baselines_compared.md](baselines_compared.md) ничего не измеряет.

## Что B1 гарантирует независимо от ответа модели

- `predicted_eids` — подмножество `allowed_evidence_ids` инстанса;
- `issue_tags` — только из словаря `schemas/prediction.schema.json`, всё
  остальное отбрасывается;
- `verdict` — один из четырёх, иначе `insufficient`;
- `confidence` зажат в `[0, 1]`;
- дубликаты в `predicted_eids` и `issue_tags` схлопываются;
- `system_info.model` — объявленный идентификатор модели, никогда не команда
  запуска и не имя python-функции.

## Безопасный отказ

Если ответ модели не разобрался после всех повторов, B1 записывает:

- `verdict`: `insufficient`
- `confidence`: `0.0`
- `predicted_eids`: `[]`
- `issue_tags`: `[]` — своего тега вроде `model_parse_failure` в словаре схемы
  нет, и выдумывать его нельзя: предсказание перестанет проходить валидацию
- `abstain`: `true`

Причина каждого отказа печатается в stderr с номером попытки, а прогон, где в
отказ ушли **все** инстансы, завершается кодом `1`. Это важно: evaluator считает
selective risk, coverage и AURC, и без этого мёртвая модель дала бы метрики
образцово осторожной системы вместо ошибки конфигурации.

## Доступ к модели

Штатный способ — `--model-api`: вызов по OpenAI-совместимому API с параметрами
из `.env` (`SCIAUDIT_BASE_URL`, `SCIAUDIT_MODEL`, `SCIAUDIT_API_KEY`). К бэкенду
это не привязано: для локального vLLM адрес будет `http://localhost:8000/v1`,
для внешнего провайдера — его URL.

```bash
python -m sciaudit.baselines.model_client --check   # заполнен ли .env, без сети
python -m sciaudit.baselines.model_client --ping    # и отвечает ли эндпоинт
python -m sciaudit.baselines.b1_bm25_llm \
  --input data_public/public_dev/inputs.jsonl \
  --output predictions.jsonl --top-k 3 --model-api
```

`--check` отвечает только на вопрос «заполнена ли настройка» и в сеть не ходит:
он годится для CI, где ключа нет. Что эндпоинт жив и что бюджета токенов хватает
на ответ, показывает `--ping`, и это разные вопросы.

### Reasoning-модели и `max_tokens`

У модели с рассуждением рассуждение списывается из того же лимита `max_tokens`,
что и ответ, а ответ идёт после него. На тесном лимите модель думает до упора,
`content` приходит пустым при `finish_reason=length`, и прогон уходит в
безопасный отказ целиком. Первый живой прогон на `gpt-oss:120b-cloud` при
`max_tokens: 512` дал ровно это. Сейчас в `configs/models.yaml` стоит `2048`;
обрезанный ответ клиент опознаёт отдельно и прямо называет причину, а не выдаёт
за поломку эндпоинта.

`--model-command` остаётся запасным путём для нестандартного инференса. У него
две цены: температуру контролирует сама команда, поэтому воспроизводимость на
вашей совести, а ключ в строке команды виден в `ps` и в истории оболочки.
